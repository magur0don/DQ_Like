# DQ-Like RPG プロジェクト

本プロジェクトは、ドラクエ風（DQ-Like）の王道RPGシステムをUnityで構築するための学習・教育用リポジトリです。
このリポジトリは、RPGの根幹となる「フィールド探索」「エンカウントとバトル」「データ管理（ステータスやインベントリ）」といった要素を、役割ごとに整理して実装することを目的に作られています。プログラミングの設計思想（デザインパターンやコンポーネント指向）を学ぶ教材として活用できます。

---

## 🎮 基本的な操作方法（想定）

- **移動 (Move)**: `W/A/S/D` または `矢印` キー
- **調べる (Interact)**: `E` キー
- **会話のページ送り (MessageNext)**: `左クリック`
- **インベントリを開く (Inventory)**: `I` キー
- **装備／ステータスを開く (Equipment)**: `P` キー
- **フィールドギミック**: 看板(`SignInteract`)や宝箱(`ChestInteract`)、NPC(`NPCInteract`)に近づいて `E` キーを押すことでインタラクト可能
- **バトルへの突入**: フィールド上を歩いている敵シンボル(`EnemySymbol`)に接触する（シンボルエンカウント方式）

## 📚 スクリプトの役割と設計思想（教育用ドキュメント）

このプロジェクトでは、ゲームの各機能がフォルダ（Namespace / 役割）ごとに分割されています。  
どこにどのようなコードを書くべきか、「疎結合（各処理が独立して作られている状態）」を保つための設計が学べます。

### 1. 🗃️ Data (データ定義 / ScriptableObject)
ゲーム内のマスターデータ（能力値やアイテム情報）を定義する層です。`ScriptableObject` を活用することで、プランナー（非プログラマー）でもUnityエディターからパラメータ調整がしやすくなるメリットがあります。

- **`ItemData` / `EnemyData` / `EquipmentData` / `DialogData`**
  アイテムや敵、装備品、会話文などの個別のデータを定義します。
- **`EnemyDatabase`**
  ゲーム内に存在するすべての敵データをリストとしてまとめ、IDなどで検索できるようにする「データベース」の役割を果たします。
- **`ExpTable`**
  次のレベルに上がるために必要な経験値をテーブル（表）として定義します。
- **`PlayerStatus`**
  プレイヤーの「初期ステータス」や「基準となる成長データ」を定義します。

### 2. 🌍 Field (フィールドシステム)
プレイヤーがマップを探検するための機能群です。

- **`PlayerController`**
  プレイヤーの移動入力処理や、アニメーション操作などを担います。
- **`CameraFollow`**
  カメラがプレイヤーを追いかける処理を担当します（簡易版のCinemachineに近い役割）。
- **`IInteractable` (インターフェース)**
  「調べることができる」という振る舞いだけを定義した設計図（インターフェース）です。これを使うことで、プレイヤー側は「目の前にあるのが宝箱か看板なのか」を気にせず、単に「調べる(`Interact`)」という命令を送るだけで済むようになります。
- **`ChestInteract` / `SignInteract` / `NPCInteract` / `ShopManager`**
  上記の `IInteractable` を継承して、「アイテムを入手する」「会話ウィンドウ(`DialogUI`)を開く」などの固有の振る舞いを実装したコンポーネントです。
- **`EnemySymbol`**
  フィールドをうろつく敵。プレイヤーの方向を向く(`LookAt`/`Slerp`)処理や、接触した際に `BattleManager` に出現する敵のIDを渡してバトルシーンへ飛ばす役割を持ちます。

### 3. ⚔️ Battle (バトルシステム)
戦闘専用のシーンで完結する機能群です。

- **`BattleManager`**
  戦闘の進行（コマンド選択 → 攻撃 → 敵ターン → 勝利/敗北）を管理する **ステート（状態）マシン** の中心です。`PlayerState` からプレイヤーの現在のHPを引き出し、勝利した経験値やお金をまた `PlayerState` に返却するまでの一連のフローをまとめます。
- **`EnemyBattleInfo`**
  敵の `EnemyData`（マスターデータ）と、実際のバトル中のステータス（現在HPなど）を分けて管理するためのクラスです。
- **`EnemyAnimator` / `EnemyStatusUI`**
  敵がダメージを受けた際のアニメーションや、HPバーなどの視覚的なフィードバックを制御します。
- **`LevelSystem`**
  戦闘勝利時に経験値を計算し、レベルアップの処理を行うロジッククラスです。

### 4. 🖼️ UI (ユーザーインターフェース)
画面の表示更新やボタンクリックといった入力を受け取る部分です。

- **`InventoryUI` / `StatusUI` / `DialogUI`**
  `InventoryManager` や `PlayerState` といった「システム(裏側)」のデータをもとに、画面に情報を表示したり、ボタンを押した結果をシステムへ伝達します。データの処理と表示が切り離されていることがポイントです。
- **`InventoryItemSlot` / `EquipmentButton`**
  UI内にたくさん並ぶ「リストの1枠」を管理するスクリプトです。
- **`ResultManager`**
  戦闘終了時やゲーム完了時のリザルト画面から、もう一度フィールドへ戻る(`Retry`)、あるいはアプリを修了(`Exit`)させる処理を管理します。

### 5. ⚙️ Utility (便利機能 / システム管理)
ゲーム全体で共有したいデータや機能を管理する層です。**シングルトン (`Singleton`) パターン** と `DontDestroyOnLoad` が使われており、シーンを遷移しても破棄されず、どこからでも `Hoge.Instance` の形でアクセスできるようになっています。

- **`PlayerState`**
  現在のHP(`CurrentHP`)や所持金(`CurrentGold`)、現在着ている装備の値などを保持します。これが **「プレイヤー状態の唯一の情報源 (Single Source of Truth)」** となります。
- **`InventoryManager` / `EquipmentManager`**
  アイテムの取得・消費(`UseItem`)、装備の付け外しを管理します。アイテム残量が `0` になった時はリストから除外するなどの内部ロジックを担います。
- **`GameState`**
  現在「メニューを開いている最中か」などの、グローバルなゲームの状態を保持します。
- **`BGMManager` / `PlayBGMOnStart`**
  フィールドとバトルをまたいでも曲が途切れないように音楽を管理するシステムです。
- **`InventryEntry`**
  `ItemData` (アイテムの種類) と `Count` (個数) をまとめた専用のクラスです。
- **`MenuButton`**
  汎用的なボタン操作をまとめたものです。
- **`QuestFlag`** / **`DebugController`**
  進行フラグの管理や、開発時専用のデバッグツールを提供します。

## 🎯 本プロジェクトから学べること（まとめ）
1. **ScriptableObjectによるデータ指向設計**:
   ステータスやアイテムを `MonoBehaviour` でハードコーディングせず、データのみのアセットとして切り離す技術。
2. **シングルトンパターンの適切な利用**:
   `BGMManager` や `PlayerState` のように、常に1つだけ存在しなければならないシステムを破綻なく制御する方法。
3. **インターフェース(`IInteractable`)を通じたポリモーフィズム**:
   「宝箱」「看板」「店」を別々のクラスでありながら、共通の振る舞い（調べる）として扱うことで、プレイヤー側の処理をシンプルに保つオブジェクト指向の強み。
4. **シーン間のデータ引き継ぎ**:
   フィールド ↔ バトル間で、現在のHPや出現する敵のIDをどうやって持ち越すかという実践的なステート管理。
